# Техническое задание: QA Assistant

---

## 1. Описание проекта

**QA Assistant** — веб-приложение для автоматической генерации тест-кейсов из документов требований с использованием ИИ-агента (Qwen/Qwen2.5-72B-Instruct).

**Цель:** Сократить рутинную работу тестировщика по преобразованию описательных требований в проверяемые сценарии с 5–10 часов до 2–5 минут на один документ.

**Ключевые функции:**
- Загрузка документов: PDF, DOCX, DOC (legacy), Markdown
- Извлечение текста с сохранением структуры
- Чанкинг и анализ ИИ-агентом
- Экспорт результатов в CSV, готовый к импорту в TestRail/Zephyr

**Технологический стек:**
- Python 3.14+
- Flask 3.0+
- Pandas, python-docx, pypdf, pywin32 (Windows)
- ИИ-агент API (Qwen/Qwen2.5-72B-Instruct)

## 3. Функциональные требования

### 3.1. Обработка документов

#### Загрузка документа
- **Тип:** Обязательный (MUST HAVE)
- **Описание:** Пользователь загружает документ через веб-интерфейс в одном из поддерживаемых форматов.


**Форматы** - PDF, DOCX, DOC, Markdown (.md)
**Размер файла** - Максимум 100 МБ 
**Конвертация DOC** - Windows: pywin32, Linux: sharepoint-to-text

**Критерии приемки:**
- [ ] На экране отображается имя и размер загруженного файла
- [ ] Кнопка "Генерировать" становится активной после загрузки
- [ ] При выборе недопустимого формата отображается ошибка: `"Поддерживаются только PDF, DOCX, DOC и Markdown-файлы"`
- [ ] При превышении размера — ошибка: `"Размер файла превышает допустимый лимит (100 МБ)"`
- [ ] При поврежденном файле — ошибка: `"Не удалось извлечь текст из файла. Проверьте его целостность."`

#### Извлечение текста
- **Тип:** Обязательный (MUST HAVE)
- **Описание:** Система извлекает текст из загруженного документа с сохранением структуры.

**Требования:**
- [ ] Заголовки, списки, таблицы распознаются корректно
- [ ] Для DOC (legacy) применяется конвертация в DOCX перед извлечением
- [ ] Для PDF используется `pypdf` или `pdfplumber` с анализом таблиц
- [ ] Для Markdown сохраняются элементы разметки (bold, italic, lists, tables)

**Критерии приемки:**
- [ ] Тест-кейсы генерируются только для корректно извлеченного текста
- [ ] Пустой документ → сообщение: `"Файл не содержит текста. Проверьте его содержимое."`
- [ ] Для медленного интернета отображается прогресс-бар: `"Извлечение текста."`

#### Чанкинг
- **Тип:** Обязательный (MUST HAVE)
- **Описание:** Длинные документы разбиваются на фрагменты (чанки) для обработки ИИ-агентом.

**Параметры чанкинга (настраиваемые через `.env`):**
| Параметр | Значение по умолчанию | Описание |
|----------|------------------------|----------|
| `CHUNK_SIZE` | 4000 | Макс. длина чанка (символы) |
| `CHUNK_OVERLAP` | 200 | Перекрытие чанков (символы) |
| `CHUNK_METHOD` | `header` | Метод разбиения: `header` (по заголовкам), `fixed` (по длине), `recursive` (адаптивно) |

**Критерии приемки:**
- [ ] Чанки создаются с учетом заголовков (не разрываются посередине заголовка)
- [ ] При превышении лимита страниц (>100) отображается предупреждение: `"Документ длинный, обработка может занять несколько минут. Продолжить?"`
- [ ] Для каждого чанка используется `CHUNK_SYSTEM_PROMPT` (строгий, без выдумывания требований)

### 3.2. Генерация тест-кейсов

#### Запуск генерации
- **Тип:** Обязательный (MUST HAVE)
- **Описание:** Пользователь инициирует генерацию тест-кейсов по загруженному документу.

**Последовательность действий:**
1. Пользователь загружает документ и нажимает "Генерировать"
2. Система отображает индикатор загрузки: `"Генерация тест-кейсов..."`
3. Происходит извлечение текста → чанкинг → отправка в API → валидация результата

**Критерии приемки:**
- [ ] При успешной генерации пользователь получает CSV-файл с колонками: `Name`, `Status`, `Step`, `Expected Result`
- [ ] При ошибке API отображается сообщение: `"Не удалось подключиться к сервису анализа. Проверьте подключение или повторите попытку."`
- [ ] При отсутствии требований в документе: `"В документе не обнаружено требований. Проверьте файл."`
- [ ] При пустом ответе API: `"Сервис анализа не сгенерировал тест-кейсы. Повторите попытку."`

#### Интеграция с ИИ-агентом
- **Тип:** Обязательный (MUST HAVE)
- **Описание:** Система вызывает ИИ-агент (Qwen/Qwen2.5-72B-Instruct) через REST API.

**Требования:**
- [ ] Используется API endpoint `QA_ASISTANT_API_URL` (настраивается в `.env`)
- [ ] В запросе используется `DEFAULT_SYSTEM_PROMPT` (для полного документа) и `CHUNK_SYSTEM_PROMPT` (для чанков)
- [ ] Ответ ИИ валидируется и приводится к формату CSV

**Критерии приемки:**
- [ ] Все запросы и ответы сохраняются в `uploads/debug/<uuid>/`
- [ ] При таймауте (>5 мин) происходит автоматический retry (max 3 раза, с задержкой 10 сек)
- [ ] При ошибке 503: `"Сервис анализа временно недоступен. Повторите через 5 минут."`
- [ ] При ошибке 429: `"Превышен лимит запросов к API. Подождите 1 час."`

#### Валидация результата
- **Тип:** Обязательный (MUST HAVE)
- **Описание:** Проверка корректности и полноты сгенерированных тест-кейсов.

**Требования:**
- [ ] CSV содержит только валидные строки (не пустые)
- [ ] Строки с пустыми шагами отбрасываются (только заголовок CSV остаётся)
- [ ] При некорректном JSON от API сохраняется необработанный ответ: `"Сервис вернул некорректный результат. Свяжитесь с администратором."`

**Критерии приемки:**
- [ ] CSV соответствует формату TestRail/Zephyr
- [ ] Пустые результаты отображаются как CSV с заголовком, но без строк

### 3.3. Экспорт результатов

####Экспорт в CSV
- **Тип:** Обязательный (MUST HAVE)
- **Описание:** Пользователь скачивает сгенерированные тест-кейсы в CSV-файле.

**Требования:**
- [ ] Формат CSV соответствует спецификации TestRail/Zephyr
- [ ] Колонки: `Name`, `Status`, `Step`, `Expected Result`
- [ ] `Status` всегда `"Approved"`
- [ ] Таблицы преобразуются в несколько шагов (одна таблица = несколько строк CSV)
- [ ] Кодировка: UTF-8 с BOM для Excel

**Критерии приемки:**
- [ ] Файл скачивается с именем: `test_cases_YYYYMMDD_HHMMSS.csv`
- [ ] При отсутствии кейсов CSV содержит только заголовок (файл не пустой)
- [ ] При превышении лимита Excel (32767 символов в ячейке) отображается предупреждение: `"Некоторые шаги были усечены. Проверьте DOCX-версию."`

#### Экспорт в DOCX (SHOULD HAVE)
- **Тип:** Важный для UX (SHOULD HAVE)
- **Описание:** Пользователь скачивает результат в DOCX для правки в Word.

**Требования:**
- [ ] Структура сохранена: заголовки, списки, таблицы
- [ ] Файл сохраняется в `test_cases_YYYYMMDD_HHMMSS.docx`

**Критерии приемки:**
- [ ] DOCX открывается в Word без ошибок форматирования

#### Уведомление о завершении (SHOULD HAVE)
- **Тип:** Важный для UX (SHOULD HAVE)
- **Описание:** Пользователь получает уведомление при завершении генерации.

**Требования:**
- [ ] При длительной генерации (>30 сек) и переходе на другую вкладку показывается нотификация: `"Генерация завершена. Скачать результат?"`

**Критерии приемки:**
- [ ] Уведомление не мешает работе в других вкладках
- [ ] При нажатии "Скачать" начинается загрузка файла

**Критерии приемки:**

#### История загрузок (NICE TO HAVE)

## 4. Нефункциональные требования

### 4.1. Производительность

| Требование | Описание | Целевое значение |
|------------|----------|------------------|
| **Время загрузки документа** | Суммарное время до завершения генерации | ≤ 5 минут для документа до 50 страниц |
| **Время API-вызова** | Среднее время ответа ИИ-агента | ≤ 3 минуты |
| **Отклик интерфейса** | Время отклика кнопок и загрузки | ≤ 200 мс |

### 4.2. Надёжность

- **Обработка ошибок:** Все ошибки должны обрабатываться без сбоев в работе приложения
- **Идемпотентность:** Повторная генерация одного документа должна давать идентичный результат
- **Резервное копирование:** Отладочные данные сохраняются в `uploads/debug/<uuid>/`

### 4.3. Безопасность

- **Токены:** Не хранятся в коде, только в `.env`
- **Файлы:** Запрет загрузки файлов с расширением `.exe`, `.bat` и т.д.
- **Конфиденциальность:** Все файлы из `uploads/` должны быть исключены из репозитория (`.gitignore`)

### 4.4. Поддерживаемость

- **Модульность:** Структура кода по слоям: `app/`, `integrations/`, `tests/`
- **Тестирование:** Новая бизнес-логика покрывается Pytest-тестами
- **Документация:** Все функции и классы должны иметь docstrings

## 5. Описание обработки ошибок

### 5.1. Ошибки валидации

| Сценарий | Ошибка | UX-решение |
|----------|--------|------------|
| Недопустимый формат файла | `"Поддерживаются только PDF, DOCX, DOC и Markdown-файлы"` | Подсветка ошибки, список допустимых форматов |
| Пустой файл | `"Файл не содержит текста. Проверьте его содержимое."` | Запрос перезагрузки |
| Повреждённый файл | `"Не удалось извлечь текст из файла. Проверьте его целостность."` | Запрос перезагрузки другого файла |
| Некорректный CSV-результат | `"Сервис вернул некорректный результат. Свяжитесь с администратором."` | Кнопка "Сохранить необработанный ответ" |

### 5.2. Отсутствие данных

| Сценарий | Ошибка | UX-решение |
|----------|--------|------------|
| В документе нет требований | `"В документе не обнаружено требований. Проверьте файл."` | Предложение загрузить другой файл |
| API вернул пустой ответ | `"Сервис анализа не сгенерировал тест-кейсы."` | Кнопка "Повторить" с настройками чанкинга |

### 5.3. Сетевые ошибки

| Сценарий | Ошибка | UX-решение |
|----------|--------|------------|
| Таймаут API (>5 мин) | `"API недоступен. Проверьте подключение или повторите попытку."` | Автоматический retry (max 3 раза, задержка 10 сек) |
| Ошибка 503 (сервис недоступен) | `"Сервис анализа временно недоступен. Повторите через 5 минут."` | Планировщик повторов: 5, 15, 30 минут |
| Ошибка 429 (лимит запросов) | `"Превышен лимит запросов к API. Подождите 1 час."` | Кнопка "Уведомить, когда лимит сбросится" |

### 5.4. Неавторизованный доступ

| Сценарий | Ошибка | UX-решение |
|----------|--------|------------|
| Отсутствует токен | `"Не настроен API-токен. Перейдите в настройки."` | Кнопка "Настроить токен" |
| Недействительный токен | `"Токен недействителен. Обновите его в настройках."` | Кнопка "Изменить токен" |

## 6. Форматы и спецификации

### 6.1. Формат CSV

| Колонка | Описание | Пример |
|---------|----------|--------|
| `Name` | Название тест-кейса | `"Тест на проверку входа в систему"` |
| `Status` | Статус (всегда `"Approved"`) | `"Approved"` |
| `Step` | Шаги теста (для таблиц: один шаг = одна строка) | `"1. Ввести логин\n2. Ввести пароль\n3. Нажать 'Войти'"` |
| `Expected Result` | Ожидаемый результат | `"Вход в систему успешно выполнен"` |

**Правила:**
- Таблицы: одна таблица = несколько строк CSV
- Пустые шаги: отбрасываются (только заголовок CSV остаётся)
- Кодировка: UTF-8 с BOM для Excel
