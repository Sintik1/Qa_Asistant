# Product Idea: QA Assistant

## 1. Основная идея

**QA Assistant** — веб-приложение для автоматической генерации тест-кейсов на основе документов требований с помощью искусственного интеллекта. Приложение позволяет извлечь текст из PDF, DOCX, DOC и Markdown-файлов, проанализировать его ИИ-агентом и получить структурированный CSV-файл с готовыми тест-кейсами, готовыми к импорту в системы управления тестированием (TestRail, Zephyr и др.).

## 2. Решаемая проблема

Современные процессы тестирования ПО сталкиваются с рутинной и трудоемкой задачей: **превращение описательных требований в проверяемые сценарии**. Тестировщики вынуждены выполнять:
- Проверка всех требований в проекте
- Ручной перенос требований из документов в формат тест-кейсов
- Анализ каждого абзаца на наличие скрытых условий и сценариев
- Поддержание единообразия формулировок и уровня детализации
- Повторная обработка при каждом обновлении документа

Это приводит к:
- Значительной трате времени (5–10 часов на один документ)
- Пропуску неочевидных требований
- Субъективной интерпретации формулировок
- Низкой воспроизводимости результатов между разными тестировщиками

**QA Assistant** решает эти проблемы, автоматизируя обработку и обеспечивая единообразный, проверяемый вывод.

## 3. Целевая аудитория

### Основные пользователи
- **Тестировщики и QA-инженеры** — получают готовые тест-кейсы, сокращая время подготовки
- **Бизнес-аналитики и Product Owners** — валидируют покрытие требований и согласуют сценарии

### Второстепенные пользователи
- **Разработчики** — используют результаты как техническую документацию
- **Руководители команд** — контролируют качество и полноту тестового покрытия

### Контекст использования
IT-компании любого размера, где есть процессы управления требованиями и тестирования: стартапы, аутсорс-компании, корпоративные ИТ-подразделения.

## 4. MVP-функции (минимум необходимого для релиза)

### 4.1. Загрузка и обработка документов
**Обязательно для MVP**: система не может работать без загрузки входных данных.

- **Форматы**: PDF, DOCX, DOC (legacy), Markdown
- **Извлечение текста**: с сохранением структуры (заголовки, списки, таблицы)
- **Автоматическая конвертация**: `.doc` на Windows через `pywin32`, `sharepoint-to-text` на Linux

> **Зачем нужно**: фундаментальный входной поток данных. Без загрузки документов система не может функционировать.

### 4.2. Генерация тест-кейсов на основе ИИ
**Основная ценность продукта**: без этого функционала приложение не решает задачу пользователя.

- **Чанкинг**: разбиение документов на фрагменты для обработки (по заголовкам, с перекрытием)
- **API-интеграция**: вызов ИИ агента (Qwen/Qwen2.5-72B-Instruct) через REST API
- **Структурированный вывод**: CSV с фиксированными колонками (`Name`, `Status`, `Step`, `Expected Result`)

> **Зачем нужно**: основная ценность продукта — автоматическая генерация тест-кейсов на основе требований. Без этого функционала приложение не решает задачу пользователя.

### 4.3. Экспорт результатов в CSV
**Условие завершения**: пользователь должен получить результат, который можно сразу использовать.

- **Формат CSV**: стандартный, соответствующий форматам TestRail, Zephyr
- **Валидация**: отбрасывание пустых результатов (только заголовок без строк)
- **Готовность к импорту**: структура CSV соответствует форматам, принимаемым системами управления тестированием

> **Зачем нужно**: пользователь должен получить результат, который можно сразу импортировать в рабочие инструменты. CSV — универсальный и ожидаемый формат.

## 5. Краткие технические детали (для реализации)

- **Стек**: Python 3.14+, Flask 3.0+, Pandas, python-docx, pypdf
- **ИИ**: Леопольд API (Qwen/Qwen2.5-72B-Instruct)
- **Архитектура**: Монолитное веб-приложение, модульная структура
- **Настройка**: Переменные окружения (`.env`) для API-токена и URL
