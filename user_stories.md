# User Story Mapping: QA Assistant

---

## 1. Personas (Роли пользователей)

### 1.1. Тестировщик (QA-инженер)
- **Роль**: Основной пользователь, создающий и валидирующий тест-кейсы
- **Цель**: Получить готовые тест-кейсы из документов требований с минимальными ручными правками


### 1.2. Бизнес-аналитик (BA)
- **Роль**: Валидатор покрытия и согласователь требований
- **Цель**: Убедиться, что все требования покрыты тестами и сценарии соответствуют бизнес-логике

---

## 2. User Journeys (Сценарии использования)

### 2.1. Счастливый путь (Main Success Scenario)

**Пользователь**: QA 

1. QA открывает приложение
2. Загружает документ требований (PDF/DOCX)
3. Нажимает "Генерировать тест-кейсы"
4. Система извлекает текст, разбивает на чанки, отправляет в API
5. Получает CSV-файл с готовыми тест-кейсами
6. Импортирует CSV в TestRail
7. Проверяет покрытие в отчете

**Время выполнения**: 2–5 минут (в зависимости от размера документа)



**Пользователь**: Бизнес-аналитик 

1. Бизнес-аналитик  загружает документ
2. Система генерирует кейсы, но пропускает часть требований
3. Бизнес-аналитик  запускает повторную генерацию с другими параметрами чанкинга
4. Получает обновленный CSV
5. Экспортирует в DOCX для правки в Word
6. Вносит правки и повторно генерирует

### 2.3. Сценарий обработки ошибки

**Пользователь**: QA

1. QA загружает документ
2. Система возвращает ошибку API (таймаут или недоступность)
3. Получает сообщение об ошибке с рекомендацией повторить
4. Повторяет попытку через 10 секунд
5. Успешно получает результат

---

## 3. User Stories (Истории по приоритетам)

### 3.1. MUST HAVE (Обязательные для MVP)

#### Story M1: Загрузка документа
**Как** тестировщик, **я хочу** загрузить документ требований в формате PDF/DOCX/DOC/Markdown, **чтобы** система могла извлечь из него текст.

**Критерии приемки**:
- Пользователь открыл страницу, и в интерфейсе есть кнопка "Выбрать файл"
- Пользователь выбирает файл с расширением .pdf, .docx, .doc, .md
- Файл загружается, и система отображает превью имени файла и размера, и кнопка "Генерировать" становится активной

**Для негативного кейса**
- Пользователь выбирает недопустимый формат
- Отображается ошибка: "Поддерживаются только PDF, DOCX, DOC и Markdown-файлы"

**Edge Cases**:
- Файл весит >100 МБ: ошибка "Размер файла превышает допустимый лимит (100 МБ)"
- Файл поврежден: ошибка "Не удалось извлечь текст из файла. Проверьте его целостность."
- Медленное интернет-соединение: прогресс-бар "Извлечение текста."

---

#### Story M2: Генерация тест-кейсов
**Как** тестировщик, **я хочу** нажать кнопку "Генерировать тест-кейсы", **чтобы** система проанализировала документ и выдала структурированный CSV-файл.

**Критерии приемки**:
- Пользователь загрузил документ, and нажал "Генерировать"
- Система отображает индикатор загрузки "Генерация тест-кейсов..."
- Генерация завершена успешно
- Пользователь получает CSV-файл с колонками: Name, Status, Step, Expected Result
**Для негативного кейса**
- Генерация не удалась (API недоступен)
- Отображается ошибка "Не удалось подключиться к сервису анализа. Проверьте подключение или повторите попытку."

**Edge Cases**:
- Документ не содержит требований: сообщение "В документе не обнаружено требований. Проверьте файл."
- Документ слишком длинный (>100 страниц): предупреждение "Документ длинный, обработка может занять несколько минут. Продолжить?"
- API вернул пустой ответ: ошибка "Сервис анализа не сгенерировал тест-кейсы. Повторите попытку."

---

#### Story M3: Экспорт результатов в CSV
**Как** тестировщик, **я хочу** загрузить сгенерированные кейсы в CSV, **чтобы** импортировать их в TestRail или Zephyr.

**Критерии приемки**:
- Генерация завершена
- На экране отображается кнопка "Скачать CSV"
- Пользователь нажимает "Скачать CSV"
- Файл скачивается с именем в формате `test_cases_YYYYMMDD_HHMMSS.csv`
- Открывается файл в Excel/Notepad
- Колонки соответствуют: Name, Status, Step, Expected Result


**Edge Cases**:
- Нет кейсов: CSV содержит только заголовок, файл не пустой
- Символы Unicode: файл сохраняется в UTF-8 с BOM для Excel
- Превышение лимита колонок в Excel (32767 символов): предупреждение "Некоторые шаги были усечены. Проверьте DOCX-версию."

---


### 3.2. SHOULD HAVE (Важные для UX, но не критичные)

#### Story S1: Повторная генерация с другими параметрами
**Как** бизнес-аналитик, **я хочу** нажать "Перегенерировать" с другими параметрами чанкинга, **чтобы** улучшить качество результатов.

**Критерии приемки**:
- Документ уже обработан
- Отображается кнопка "Перегенерировать с настройками"
- Пользователь нажимает кнопку и меняет параметры (размер чанка, перекрытие)
- Система перезапускает обработку с новыми параметрами

---

#### Story S2: Экспорт в DOCX для правки
**Как** бизнес-аналитик, **я хочу** скачать результат в DOCX, **чтобы** внести правки в Word и вернуться в систему.

**Критерии приемки**:
- Генерация завершена
- Отображается кнопка "Скачать DOCX"
- Пользователь нажимает "Скачать DOCX"
- Файл скачивается с именем `test_cases_YYYYMMDD_HHMMSS.docx`
- Открывается в Word
- Структура сохранена (таблицы, заголовки)

---

#### Story S3: Уведомление о завершении
**Как** тестировщик, **я хочу** получить уведомление при завершении генерации, **чтобы** не следить за индикатором.

**Критерии приемки**:
- Генерация длится >30 секунд, and пользователь находится на другой вкладке
- Через нотификацию: "Генерация завершена. Скачать результат?"
- Пользователь нажимает "Скачать"
- Файл начинает скачиваться

---

### 3.3. NICE TO HAVE (Расширения для будущего)


#### Story N1: История загрузок
**Как** тестировщик, **я хочу** видеть историю обработанных документов, **чтобы** быстро найти результаты по прошлым сессиям.

#### Story N2: Интеграция с Jira
**Как** QA, **я хочу** загрузить ссылку на задачу в Jira, **чтобы** система извлекла требования из описания.

#### Story N3: Экспорт в JSON/XML
**Как** QA, **я хочу** получить результат в JSON/XML, **чтобы** использовать его для автоматических тестов.

---

## 4. Обработка ошибок и Edge Cases

### 4.1. Ошибки валидации

**Сценарий**   
Недопустимый формат файла 
**Ошибка**
"Поддерживаются только PDF, DOCX, DOC и Markdown-файлы"
**UX-решение**
Подсветка ошибки, список допустимых форматов 

**Сценарий** 
Пустой файл
**Ошибка**
"Файл не содержит текста. Проверьте его содержимое."
**UX-решение**
Запрос перезагрузки 

**Сценарий** 
Некорректный CSV-результат
**Ошибка**
"Сервис вернул некорректный результат. Свяжитесь с администратором." 
**UX-решение**
Кнопка "Сохранить необработанный ответ" для отладки

---

### 4.2. Отсутствие данных

**Сценарий** 
В документе нет требований
**Ошибка**
"В документе не обнаружено требований. Проверьте файл.
**UX-решение**
"Предложите загрузить другой файл 

**Сценарий**
API вернул пустой ответ
**Ошибка**
"Сервис анализа не сгенерировал тест-кейсы."Кнопка "
**UX-решение**
Повторить" с настройками чанкинга

---

### 4.3. Сетевые ошибки

**Сценарий**
Таймаут API (>5 мин)
**Ошибка**
"API недоступен. Проверьте подключение или повторите попытку."
**UX-решение**
Автоматический retry через 10 сек (max 3 раза)

**Сценарий**
Ошибка 503 (сервис недоступен)
**Ошибка**
"Сервис анализа временно недоступен. Повторите через 5 минут."
**UX-решение**
Планировщик повторов: 5, 15, 30 минут

**Сценарий**
Ошибка 429 (лимит запросов)
**Ошибка**
"Превышен лимит запросов к API. Подождите 1 час."
**UX-решение**
Кнопка "Уведомить, когда лимит сбросится"

---

### 4.4. Неавторизованный доступ

**Сценарий**
Отсутствует токен
**Ошибка**
"Не настроен API-токен. Перейдите в настройки."
**UX-решение**
Кнопка "Настроить токен"

**Сценарий**
Недействительный токен 
**Ошибка**
"Токен недействителен. Обновите его в настройках."
**UX-решение**
Кнопка "Изменить токен"
